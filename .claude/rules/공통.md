> 핵심만 여기 사본으로 둔다. 원본이 바뀌면 `tooling/web-repo/web-repo.ps1 -Push` 를 다시 돌려 덮어쓴다 — 여기서 직접 고치지 않는다.

## 최상위 규칙

- 디버깅: **원인 명확 → 최소 수정 → 핵심 재현 테스트 → 실패 시 추가 진단**. 원인이 불명확하면 관련 코드만 진단해 원인을 먼저 좁힌다.
- 운영 이상 보고: **주장을 기록·실측과 대조 → 오해와 실제 피해를 가른다 → 피해에만 선택지(추천 1개)**. 다른 세션·에이전트의 설명은 근거가 아니라 확인 대상이다.
- 코딩 전 요구사항·가정·수정 범위·완료조건을 짧게 확인한다. 이미 명확하면 재질문하지 않는다. 결과를 바꾸는 모호함만 질문한다.
- 단순함 우선: 요청하지 않은 기능, 선제적 추상화, 과도한 방어코드·설정 가능성을 추가하지 않는다.
- 수술적 변경: 필요한 파일/라인만 수정한다. 관련 없는 리팩터링·인접 코드 정리·포맷 변경 금지. 별도 문제는 보고만 한다.
- 완료조건은 제한형: 명시된 완료조건과 변경 관련 핵심 검사만 확인하고, 통과하면 끝낸다. 전체 테스트 스위트 남발·근거 없는 반복 검증 금지.
- **한국어로 결론 먼저.** 표·불릿으로 짧게. 구현 로그는 변경점·핵심 검증 결과·막힌 점만. 코드·식별자는 영어 그대로.

## 대량 작업은 probe 먼저

돈·시간을 쓰는 대량 작업(외부 LLM 수십~수백 호출 · 전 대상 재처리 · 긴 배치)은 본 실행 전에 **대상 1개 × 2~3건** probe.
형식·결과·건당 비용/시간을 확인하고, "전체 N건 × 건당 실측 = 총 얼마"를 먼저 말한 뒤 전체는 한 번만 돌린다.

## 클라우드에서 달라지는 것

- 로컬 전용 자원은 없다: `Z:` 드라이브, 로컬 GPU·SwarmUI, `Z:\Anaconda3` 파이썬, 다른 프로젝트 폴더. 이런 경로가 문서에 나오면 **로컬 기록**이다.
  필요한데 없으면 추측·대체하지 말고 무엇이 없는지 말하고 멈춘다.
- 남길 결정·맥락은 이 레포의 `CLAUDE.md`·`docs/` 에 적는다(세션 메모리는 휘발).
- Notion: 기본 기록·초안은 PRIVATE 의 해당 프로젝트 영역, "확정"은 SHARED 결정 로그, "개발해야 함"은 SHARED 개발 TODO.
  다른 프로젝트·개인 메모는 건드리지 않는다. 같은 내용이 있으면 새로 만들지 말고 갱신한다.
